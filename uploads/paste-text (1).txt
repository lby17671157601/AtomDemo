第三阶段：接入真实 AI 模型，实现项目代码生成

请继续当前 Atoms Demo 项目。保留现有工作台、原生认证、数据库表、项目 API 和权限校验，不要新建项目或推倒重做。

一、实施前检查

检查当前 Atoms 环境是否提供可用的 AI 模型服务或官方 AI 接口。

优先使用平台原生支持的模型能力。

如果需要外部 API 密钥，请先列出所需配置、费用风险和配置步骤，不要擅自开通收费服务。

在确认可用的模型接口之前，不要伪造 AI 回复或生成成功状态。

二、实现真实 AI 对话

用户在现有对话输入框中输入应用需求后，可以发起真实的模型请求。

请求必须经过受控的服务端接口，不能将 API 密钥暴露给浏览器。

将用户需求、必要的项目上下文和当前项目文件传给模型。

在界面中显示加载状态，并处理超时、限流、服务不可用和模型错误。

只有模型实际返回结果后，才能显示成功状态。

不要把模型输出直接当作可信代码执行。

三、生成并保存项目文件

模型应返回结构化的文件修改结果，例如文件路径、文件内容和修改说明。

校验文件路径，拒绝路径穿越、越权文件修改及不允许的文件类型。

将经过校验的文件修改保存到当前用户有权限访问的项目。

使用现有 project_files 数据库接口，并遵守服务端授权规则。

每次成功修改后，更新项目文件列表和 Code 面板。

如果数据库保存失败，应明确提示失败，不得显示虚假的保存成功状态。

模型生成失败时保留用户输入，允许重试。

四、支持多轮修改

例如：

第一次输入：创建一个简单的任务管理应用。

第二次输入：为任务增加完成状态。

第三次输入：增加任务筛选功能。

模型应基于当前项目文件进行增量修改，不能每次无条件覆盖整个项目。每次修改应记录必要的变更说明。

五、运行与安全边界

本阶段只实现真实模型调用、文件生成和文件持久化。

不要直接在服务器上执行任意模型生成的代码。

不要把模型返回的 HTML、JavaScript 或其他代码直接插入主应用页面执行。

Preview 暂时继续显示“运行环境尚未配置”，除非已经接入真正隔离的预览环境。

发布按钮不得伪造部署结果。

如果需要运行代码，后续阶段再接入隔离的沙箱或独立预览服务。

六、测试与报告

请运行适用的测试，至少覆盖：

模型服务未配置时的错误提示。

模型调用成功和失败处理。

未登录用户不能调用项目生成接口。

用户不能修改其他用户的项目文件。

文件路径校验。

生成结果能否写入数据库并重新读取。

多轮修改是否基于已有文件。

完成后列出实际修改的文件、需要配置的环境变量、实际执行的测试、未完成的功能，以及是否仍有收费或外部服务依赖。

不要把模拟模型响应的测试描述为真实模型端到端测试。
