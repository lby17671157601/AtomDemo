一、验证完整用户流程

使用真实浏览器和官方认证流程，逐步检查：

未登录时访问工作台是否被正确拦截。

用户完成官方登录后是否进入工作台。

页面刷新后，会话是否正确恢复。

用户是否能读取、创建和重命名自己的项目。

用户输入需求后，服务端是否真实调用 AI 模型。

AI 生成的文件是否保存到数据库。

刷新页面或重新登录后，项目和已保存文件是否仍然存在。

Code 和 History 是否反映真实的文件及修改记录。

模型服务失败或数据库失败时，界面是否明确提示错误。

登出后是否无法继续访问受保护的项目接口。

二、测试边界

只有真实执行的浏览器测试才能标记为浏览器端到端通过。

单元测试、集成测试、模拟请求和静态代码检查应分别记录。

不要将模拟认证或模拟模型调用描述为真实用户测试。

不要记录、展示或提交用户密码、Cookie、会话令牌和 API 密钥。

不要删除已有项目或真实用户数据。

不要为通过测试而关闭权限校验。

三、发现问题后的处理

优先修复阻断核心流程的问题，包括认证状态恢复、数据库读写、模型调用失败处理和文件保存一致性。

如果遇到官方认证页面限制、浏览器自动化不支持或其他环境障碍，请说明阻塞原因，并列出我需要手动完成的步骤，不要伪造测试结果。
