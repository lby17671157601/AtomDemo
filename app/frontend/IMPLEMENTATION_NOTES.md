# Atoms Demo：第二阶段交付说明

## 实现思路与取舍

本阶段保留 React + TypeScript + Vite 三栏工作台，接入 Atoms Cloud 原生认证与数据库，不配置外部收费服务，不新增依赖。前端通过现有 Web SDK 调用服务，不直接拼接后端地址，不暴露数据库凭据或服务端密钥。

认证使用 `client.auth.me()` 恢复和核验会话，`toLogin()` 进入官方托管认证，沿用只读 `AuthCallback.tsx` 处理回调，`logout()` 登出。没有创建用户表或自定义密码系统。**SDK 没有独立 signUp 方法；新用户注册依赖官方托管页面提供的入口，其可用性尚未实际验证，不能宣称真实注册已经验收通过。**

业务 API 统一位于 `/api/v1/workspace`，每个请求依赖原生服务端身份校验。项目按 `user_id` 过滤，消息与文件读取或写入前同时检查父项目归属，客户端不能指定所属用户或伪造 AI 回复角色。

表生成时发现默认 `/entities/*/all` 入口没有身份限制，因此清空三张业务表的默认路由，仅保留受保护的工作台 API。没有宣称启用数据库原生 RLS：当前通过服务端授权实现等效隔离，并测试了拒绝跨用户读取与修改。

项目删除采取**永久删除**：先锁定父项目，再在一个事务中删除全部关联消息、文件和项目。消息与文件写入也先锁定父项目，防止与删除竞争产生孤儿记录。当前关系由业务 API 管理，未添加数据库外键或唯一索引迁移。

## 当前完成程度

### 已实现

- 登录门禁、官方认证入口、会话核验、登出调用及错误提示；未认证时不挂载工作台。
- projects、messages、project_files 三张真实表；用户由原生认证管理。
- 项目列表、创建、重命名与删除；界面只有服务器成功返回后才确认操作成功。
- 项目切换时读取其消息与文件；发送时原子保存用户消息与明确标记的 AI 未配置系统消息。
- Code 只读展示数据库文件并支持文件选择；文件写入 API 支持相对路径校验与按路径更新，但本阶段没有新增手工文件编辑界面或生成假文件。
- History 从项目创建时间与已保存用户消息恢复，不是完整审计日志或代码版本历史。
- 数据请求失败有可见提示与重试入口；未发送草稿仅保留页面内存。

### 仍未实现或未验收

- AI 生成、多轮代码修改、安全构建与真实预览、应用发布继续未配置。
- 官方新用户注册、真实账号登录和登出、浏览器刷新恢复会话、重新登录恢复项目：调用链已接入，尚未完成真实账号端到端验收。
- 文件编辑 UI、草稿持久化、完整审计日志、代码版本管理未实现。
- 手机实机与已登录工作台浏览器自动化交互未验收。
- 请求超时而数据库实际提交成功时，客户端可能显示“未确认成功”；消息重试去重和幂等键尚未实现。
- 列表 API 分页，前端分批获取全部记录；超大历史的虚拟化或按需加载尚未实现。

## 数据契约及初始化

| 表 | 字段 |
|---|---|
| projects | id：自增整数；user_id：认证用户字符串 ID；name；自动 created_at / updated_at |
| messages | id：自增整数；user_id；project_id：整数；role；content；自动 created_at / updated_at |
| project_files | id：自增整数；user_id；project_id：整数；path；content；自动 created_at / updated_at |

本环境已通过平台表管理工具创建三张表并查询确认契约，真实数据库测试也已读写成功。无需要用户手工运行的迁移命令，无模拟项目种子数据。

在另一个环境重建时：先启用原生后端，再使用平台表管理能力创建上述私有表（`create_only=true`，包含 `user_id`）；自动时间字段无需在业务 schema 中定义。随后部署 `routers/workspace.py` 并确保三张默认业务路由仍为空，验证匿名访问和跨用户访问被拒绝。**重新生成表可能重写默认路由，必须重新应用并验证这些限制，不能只重建表而忽略授权。**

## 所需环境配置

- 新增自定义环境变量：**无**。
- 后端依赖平台注入的 `DATABASE_URL`，本次已确认存在并实际连接；其值不写入前端或文档。
- 官方认证、回调和 SDK 的运行配置沿用原生模板，由平台管理；未另行配置外部身份提供商、管理员密码或 API 密钥。
- 未修改系统预览配置、后端核心基础文件或受保护 ORM 文件；模型由平台表管理工具生成。

## 后续优先级

1. **P0：真实认证验收**——使用官方真实账号验证注册入口、登录、登出、刷新会话和跨账号隔离；若托管注册入口不可用，应明确作为注册功能阻塞处理，不能另建假注册。
2. **P1：可靠性与数据约束**——完善浏览器交互测试、保存幂等性、数据库外键与唯一约束、完整审计及大历史按需加载。
3. **P2：真实 AI 生成**——后端调用支持的模型（建议 gpt-5.4），校验并持久化文件结果；不让前端持有服务端密钥。
4. **P3：安全运行预览**——先建立隔离、资源和网络边界，再执行用户生成代码。
5. **P4：多轮代码修改与版本恢复**；**P5：真实项目部署**——依赖已验收的生成和运行闭环，分阶段确认后实施。
